## 🧠 ¿Qué es Suricata?

Suricata es un motor **IDS/IPS** de código abierto: inspecciona el tráfico de red en tiempo real y lo compara contra un conjunto de **reglas (firmas)**. Cuando un paquete o flujo coincide con una firma, genera una alerta en formato JSON (`eve.json`).

En este laboratorio corre en **modo IDS** (solo alerta, no bloquea) sobre la interfaz `enp0s8`, combinando dos fuentes de reglas:

- **Emerging Threats (ET Open)** — ruleset público, se actualiza con `suricata-update`.
- **Reglas custom propias** — estáticas, las mantienes tú a mano.

> Ajusta `enp0s8` al nombre real de tu interfaz en cada comando donde aparezca.

## 🧩 Parámetros del Entorno

| Parámetro | Valor |
|---|---|
| Motor IDS | Suricata (modo IDS) |
| Interfaz de monitoreo | `enp0s8` |
| Fuente de reglas pública | Emerging Threats — ET Open |

| Configuración principal | `/etc/suricata/suricata.yaml` |
| Log de eventos | `/var/log/suricata/eve.json` |
| Log de estadísticas | `/var/log/suricata/stats.log` |
| Socket de control | `/var/run/suricata/suricata-command.socket` |

## 1. 📦 Instalación

Se instala desde el PPA oficial del proyecto para obtener la versión estable más reciente.

```bash
# Agregar el repositorio oficial y actualizar índices de paquetes
sudo add-apt-repository -y ppa:oisf/suricata-stable
sudo apt update

# Instalar Suricata
sudo apt install -y suricata
```

Verificar la instalación:

```bash
suricata --build-info | head -5   # info de compilación (features, librerías)
suricata -V                        # versión instalada
```

## 2. 🔄 Actualización de Reglas (Emerging Threats)

`suricata-update` descarga y actualiza el ruleset público ET Open. **No toca las reglas custom** — esas son estáticas y las editas tú directamente.

```bash
sudo suricata-update                        # descarga/actualiza el ruleset ET Open
sudo suricata-update list-sources           # ver qué fuentes de reglas están configuradas
sudo suricata-update enable-source et/open  # habilitar una fuente adicional
```

Automatizar la actualización diaria (3:00 a.m.) y recargar en caliente al terminar:

```bash
echo "0 3 * * * root suricata-update && suricatasc -c 'reload-rules'" | sudo tee /etc/cron.d/suricata-update
```

## 5. 🌐 Interfaz de Red / Captura de Paquetes

Desactivar el *offloading* de la NIC evita que la tarjeta reensamble paquetes antes de que Suricata los vea — un reensamblado incorrecto puede ocultar un ataque.

```bash
ip -br link show   # ver interfaces disponibles

sudo ethtool -K enp0s8 rx off tx off tso off gso off gro off lro off   # desactivar offloading

sudo ethtool -k enp0s8 | grep -E "tcp-segmentation|generic-segmentation|generic-receive|large-receive"   # verificar que quedó desactivado

ethtool -l enp0s8   # colas RSS de la NIC (relevante si usas varios threads)
```

## 11. 🔁 Flujo Típico de Cambio de Configuración

- [ ] **1. Editar** `/etc/suricata/suricata.yaml` o el archivo de reglas correspondiente
- [ ] **2. Validar SIEMPRE** antes de aplicar → `sudo suricata -T -c /etc/suricata/suricata.yaml`
- [ ] **3a.** Si solo cambiaron **reglas** → recarga en caliente: `sudo suricatasc -c "reload-rules"`
- [ ] **3b.** Si cambió el **`suricata.yaml`** (af-packet, outputs, etc.) → reinicio completo: `sudo systemctl restart suricata`
- [ ] **4. Confirmar** que quedó sano → `sudo systemctl status suricata --no-pager` y `sudo suricatasc -c "iface-stat enp0s8"`

## 💡 Buenas Prácticas

- Nunca reinicies ni recargues sin validar primero (`-T -c`) — un YAML roto tumba el servicio.
- Mantén las reglas custom en un archivo separado del ruleset de ET Open, para no perderlas en una actualización.
- Revisa `iface-stat` periódicamente: los *drops* de paquetes indican que la interfaz no está dando abasto.
- El offloading de la NIC (`ethtool -K`) debe quedar desactivado mientras Suricata monitorea esa interfaz.
- Antes de una prueba de tráfico (sección 9), confirma que `tail -f eve.json` ya está corriendo en otra terminal para no perderte la alerta.
